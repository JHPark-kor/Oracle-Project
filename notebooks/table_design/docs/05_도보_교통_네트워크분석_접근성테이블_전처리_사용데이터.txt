[사용 공공 데이터]

국토교통부 국가공간정보센터, 브이월드(V-World) 「(센서스경계) 행정동경계」(2025년 1월 20일 등록), 2026년 7월 23일 내려받음.

OpenStreetMap, 서울시 보행 네트워크, 2026년 7월 31일 내려받음

한국교통연구원 국가교통DB(KTDB), 「2024년 배포 수도권 도로철도 통합 네트워크(2023-2035)」. 2026년 8월 3일 내려받음




[테이블 설계 및 데이터 전처리 과정]

도보 네트워크 구축
서울시 행정동 경계를 하나의 외곽경계로 통합한 뒤 1km 버퍼를 생성, 해당 범위를 기준으로 OSMnx 보행 네트워크를 수집함. 
서울 경계 안에서만 네트워크를 자르면 경계부 격자의 실제 최단 보행경로가 누락될 수 있어 외곽 1km를 포함하도록 설계

도보 node snapping
100m 격자 중심점과 가맹점 POI를 각각 최근접 도보 node에 연결하고, node ID와 스냅거리를 생성함. 
스냅거리 이상치 후보를 확인한 결과, 큰 값은 주로 한강·산지·외곽부 격자에서 나타났고 문화누리대상자 추정 인구가 작거나 0인 경우가 많아 분석 영향은 제한적이라고 판단함.

도보 접근성 cost 설계
도보 기준은 마을단위시설 접근 기준인 도보 약 10분·750m를 적용함. 최종 도보 접근거리는 다음과 같이 정의함.
[도보_최종거리 = 격자_스냅거리_보정 + 도보_네트워크거리 + 가맹점_스냅거리]
100m 격자는 실제 출발 위치가 중심점과 다를 수 있어 격자 내부 위치 오차를 보정함. 
격자 중심점에서 격자 내부 임의 지점까지의 거리 범위를 0~70.7m로 보고, 평균값인 35.35m를 격자 스냅거리에서 차감함. 
가맹점은 point 자료이므로 별도 보정 없이 원 스냅거리를 사용함.

도보 접근 가능 pair 생성
Dijkstra 알고리즘으로 각 격자 node에서 750m 이내 도달 가능한 node를 탐색함. 
이후 격자 스냅거리 보정값, 도보 네트워크거리, 가맹점 스냅거리를 합산해 750m 이하인 경우 격자-가맹점 접근 가능 pair로 저장함.

대중교통 네트워크 구축
KTDB 2025년 수도권 도로철도 통합 네트워크의 node, link, TransitInfo, TransitPath 자료를 사용함.
KTDB node 좌표를 KATEC 계열 좌표계로 해석해 EPSG:5179로 변환하고, 서울시 2km 버퍼 node와 그 node에 연결된 1-hop link를 포함함. 
서울 경계부에서 이동경로가 유효한 네트워크임에도 불구, 행정동 경계를 일시적으로 이탈하는 경우 고려

KTDB link 기반 네트워크 생성
KTDB link의 from_node와 to_node에 node geometry를 결합하고, 두 node를 연결하는 LineString edge를 생성함.

대중교통 노선 edge 생성 및 거리 매칭
TransitPath의 Line_ID별 node 순서를 이용해 연속 node 쌍을 생성하고, 이를 KTDB link의 from_node-to_node와 매칭해 length_m과 link_type을 결합함. 
정방향으로 매칭되지 않은 일부 node 쌍은 동일한 두 node가 반대방향 link로 존재하는지 확인해 거리값을 보완함. 
최종적으로 서울권 path edge 350,215개 중 349,985개는 정방향 매칭, 157개는 역방향 보완, 73개는 미매칭으로 제외함.

대중교통 시간 cost 설계
대중교통 접근성은 지역거점시설 접근 기준인 차량 약 20분·10km를 참고하되, KTDB 노선별 표정속도(Commercial_Speed)를 활용해 시간 cost로 계산함.
[대중교통_edge시간 = length_m / (Commercial_Speed × 1000 / 60)]
같은 from_node-to_node 조합이 여러 노선에서 반복될 경우, 시간 기준으로 가장 짧은 edge를 그래프에 사용함.

대중교통 node snapping 및 접근시간 산정
100m 격자 중심점과 가맹점 POI를 각각 최근접 대중교통 node에 연결함. 
대중교통 접근시간은 탑승 node까지의 도보시간, 대중교통 네트워크 시간, 하차 node에서 가맹점까지의 도보시간을 합산해 계산함.
[대중교통_최종시간 = 격자_탑승접근시간 + 대중교통_네트워크시간 + 가맹점_하차접근시간]
보행속도는 도보 기준과 동일하게 75m/min을 적용함. 
격자는 중심점 출발 오차를 줄이기 위해 스냅거리에서 35.35m를 차감, 가맹점은 point 자료이므로 별도 보정 없이 원 스냅거리를 사용.

배차간격 및 환승 대기시간 처리
배차간격과 환승 대기시간은 본 metric에 포함하지 않음. 
대기시간은 최초 탑승 또는 환승 시점에 발생하는 비용이므로 edge 단위로 단순 가산하기 어렵고, 같은 노선을 여러 edge 이동할 때 반복 계산될 위험임을 고려



[최종 산출물]

「문화누리_격자_가맹점_접근성_통합테이블.csv」
도보와 대중교통 기준으로 접근 가능한 격자-가맹점 pair를 통합한 최종 분석 테이블. GRID_CD, 가맹점_ID, 접근수단, 접근비용, 격자 행정구역 정보, 추정 인구 및 문화누리대상자 추정 인구, 가맹점명, 가맹점 분류, 서비스 속성 정보를 포함함.

「도보_네트워크_nodes.gpkg」
OSM 기반 서울시 도보 네트워크의 node 공간자료. 팀원이 도보 접근성 기준을 변경하여 재분석할 때 사용할 수 있는 그래프 node 데이터임.

「도보_네트워크_edges.gpkg」
OSM 기반 서울시 도보 네트워크의 edge 공간자료. edge 길이와 도로 유형 정보를 포함하며, 도보 네트워크 최단거리 재계산에 사용할 수 있음.

「도보_네트워크_graph.graphml」
OSMnx graphml 형식의 도보 네트워크 그래프 파일. NetworkX/OSMnx에서 직접 불러와 도보 최단거리 분석을 재수행할 수 있음.

「대중교통_네트워크_nodes.gpkg」
KTDB 기반 대중교통 그래프에 포함된 node 공간자료. 대중교통 그래프의 node 위치와 node_id를 포함함.

「대중교통_네트워크_edges.csv」
KTDB TransitPath와 link 거리정보를 결합해 생성한 대중교통 그래프 edge 테이블. from_node, to_node, length_m, 대중교통_edge시간, Line_ID, Mode, link_type 등을 포함하며, 대중교통 접근성 cost를 변경하여 재분석할 때 사용할 수 있음.

「격자_도보노드_연결테이블.csv」
각 100m 격자가 도보 네트워크의 어느 node에 연결되는지 정리한 테이블. GRID_CD, 도보_노드ID, 도보_스냅거리, 격자_스냅거리_보정 값을 포함함.

「격자_대중교통노드_연결테이블.csv」
각 100m 격자가 대중교통 네트워크의 어느 node에 연결되는지 정리한 테이블. GRID_CD, 대중교통_노드ID, 대중교통_스냅거리, 대중교통_스냅거리_보정, 대중교통_탑승접근시간을 포함함.

「가맹점_도보노드_연결테이블.csv」
각 문화누리카드 가맹점이 도보 네트워크의 어느 node에 연결되는지 정리한 테이블. 가맹점_ID, 도보_노드ID, 도보_스냅거리를 포함함.

「가맹점_대중교통노드_연결테이블.csv」
각 문화누리카드 가맹점이 대중교통 네트워크의 어느 node에 연결되는지 정리한 테이블. 가맹점_ID, 대중교통_노드ID, 대중교통_스냅거리, 대중교통_하차접근시간을 포함함.
