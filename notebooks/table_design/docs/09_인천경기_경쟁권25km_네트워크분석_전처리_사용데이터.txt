[테이블 설계 및 데이터 전처리 과정]

분석 범위 설정
서울 단독 네트워크 분석 결과는 보존하고, 경기·인천 외부 25km 경쟁권을 반영한 확장 네트워크 pair를 별도로 생성함. 분석 격자는 서울 100m 격자와 경기·인천 외부 25km 100m 격자를 결합하고, 분석 가맹점은 서울 가맹점과 경기·인천 가맹점을 결합함.

가맹점 분석 대상 정리
문화누리 접근성 분석 대상에서 제외하기로 한 숙박, 여행사, 교통수단은 제거함. 격자와 가맹점에는 서울여부, 시도, 시군구, 행정동 등 구분 칼럼을 유지하여 이후 접근성 산출 단계에서 서울 결과 격자와 외부 경쟁권 격자를 구분할 수 있게 함.

대용량 저장 기준
데이터 용량을 줄이기 위해 graphml, 전체 node, 전체 edge 원본 산출물은 저장하지 않음. 접근성 분석에 필요한 분석격자, 분석가맹점, 격자-노드 연결테이블, 가맹점-노드 연결테이블, 도보 접근 pair, 대중교통 접근 pair만 parquet 또는 gpkg로 저장함.

도보 네트워크 구축
기존 서울 분석과 동일하게 OSMnx 보행 네트워크를 사용함. 도보 접근성은 750m 이내 생활권 기준이므로, 도보 그래프는 서울 경계부의 누락을 줄이기 위해 서울 경계 2km buffer 내부를 기준으로 수집함.

도보 node snapping
격자 중심점과 가맹점 POI를 각각 최근접 도보 node에 연결하고, node ID와 스냅거리를 생성함. 100m 격자는 실제 출발 위치가 중심점과 다를 수 있으므로 서울 분석과 동일하게 격자 스냅거리에서 35.35m를 차감함.

도보 접근 가능 pair 생성
가맹점 node 기준 reverse Dijkstra를 실행하여 750m 이내 도달 가능한 격자를 탐색함. 최종 도보 접근비용은 다음과 같이 계산함.

도보 접근비용 = max(격자_스냅거리 - 35.35m, 0) + 도보_네트워크거리 + 가맹점_스냅거리

대중교통 네트워크 구축
KTDB 2025년 수도권 도로철도 통합 네트워크를 사용함. KTDB node 좌표는 KATEC 계열 좌표계로 해석하여 EPSG:5179로 변환함. 경쟁권 25km에 2km buffer를 추가한 범위의 node를 추출하고, 경계부 네트워크 단절을 줄이기 위해 연결 link는 1-hop 확장함.

대중교통 edge 시간 계산
TransitPath에서 Line_ID별 연속 node 쌍을 생성하고, KTDB link 거리와 매칭함. 정방향 link 거리 매칭이 되지 않는 경우 역방향 link 거리로 보완함. 노선별 표정속도(Commercial_Speed)를 이용하여 edge 이동시간을 계산함.

대중교통 node snapping
격자와 가맹점을 대중교통 그래프 node에 최근접 연결함. 격자 스냅거리는 도보 분석과 동일하게 35.35m 차감하고, 보행속도는 75m/min을 적용하여 탑승접근시간과 하차접근시간을 계산함.

대중교통 접근 가능 pair 생성
가맹점 node 기준 reverse Dijkstra를 실행하여 20분 이내 도달 가능한 격자를 탐색함. 최종 대중교통 접근비용은 다음과 같이 계산함.

대중교통 접근비용 = 격자_탑승접근시간 + 대중교통_네트워크시간 + 가맹점_하차접근시간

최종 검증
서울과 외부 25km 격자, 서울과 외부 25km 가맹점을 하나의 경쟁권으로 결합한 뒤 접근 가능 pair를 생성함. 통합 접근성 테이블은 중복 저장하지 않고, 접근성 지표 산출 단계에서 분석격자, 분석가맹점, 도보접근성, 대중교통접근성을 key 기준으로 결합하도록 설계함.
